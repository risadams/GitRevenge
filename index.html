Revenge.

what it does

All of git, none of the waiting.

Built for the repositories other clients give up on, and comfortable on small ones too.

01

A graph for big histories

History loads just ahead of where you scroll, not all at once. On the Linux kernel the aim is a first screen in under a second and 60fps scrolling.

02

Your git, not ours

It drives the git you already have, with your config, hooks, credential helpers and SSH agent. Anything you do in a terminal shows up straight away.

03

Everyday git, with undo

Stage files, hunks or single lines. Commit, stash, branch, merge, rebase, cherry-pick, reset and revert, then undo it if you change your mind.

04

History tools

Interactive rebase, a 3-pane conflict tool, file history, blame, the reflog, git notes and signature badges.

05

Previews, not just diffs

Markdown, images, CSV, JSON, YAML, TOML, LaTeX, Mermaid and PDF files can be shown rendered, next to the usual unified or split diff.

06

Nothing leaves your machine

No accounts, no cloud sync, no telemetry and no AI. The one request it makes on its own is an update check, and you can turn it off.

see it work

The hard parts of git, made visible.

Commit part of a file

Stage a hunk or a few lines, write a message, Ctrl+Enter.

Tidy a branch

Drop, squash and fixup in an editor, not a text file.

Resolve a conflict

Ours, theirs and the result side by side, then Continue.

Big repository?
# Git Revenge needs git 2.40 or newer
git --version

# A commit-graph file makes the first screen much faster
git commit-graph write --reachable

# ...and this keeps it up to date on every fetch
git config fetch.writeCommitGraph true
